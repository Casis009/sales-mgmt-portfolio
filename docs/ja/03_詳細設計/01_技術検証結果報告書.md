## 1. 検証の目的

技術選定書（第1.1版）で採用した技術のうち、実績が少ない組み合わせ・本プロジェクト固有の条件について、製造開始前に動作を確認し、手戻りのリスクを下げる。

## 4. 問題が見つかった場合の代替案

検証の結果、代替案に切り替えた項目はない。P-03 の結果によっては、以下の代替案を適用する。

| No | 想定する問題 | 代替案 | 設計への影響 | 適用 |
|---|---|---|---|---|
| P-01 | MyBatis の対応版が Spring Boot 4.1 で動作しない | Spring Boot を 4.0 系の最新パッチに下げる | 技術選定書のみ | 不要 |
| P-02 | 日本語が文字化けする、フォントを埋め込めない | ① フォント拡張の設定を見直す ② OpenPDF を直接使用して帳票を出力する | ②の場合は帳票の詳細設計・工数を見直す | 不要 |
| P-03 | ARM で動作しないライブラリがある | OCI の x86 インスタンス（AMD）を使用する | システム構成図（インスタンス種別）のみ | 未定（P-03 実施後） |
| P-04 | GitHub Actions で Testcontainers が動作しない | CI ではワークフローの services で PostgreSQL を起動して接続する | テスト基盤の設定のみ | 不要 |
| P-05 | 非同期起動・実行状況の取得が想定どおりにできない | 請求締めを同期処理とする | SCR-501 の実行状況表示、バッチ詳細設計 | 不要 |

## 6. 検証で判明した事項と対応

| No | 項目 | 判明した内容 | 対応 |
|---|---|---|---|
| 1 | 帳票の太字（P-02） | IPAexゴシックには太字の書体がないため、`bold="true"` を指定しても太字で表示されない | 帳票（RPT-01・02）では、強調を文字の大きさ・罫線で表現する。製造 6段階で帳票を作成するときに帳票設計書へ反映する |
| 2 | PDF からのテキストコピー（P-02） | 半角ハイフン「-」は、PDF から文字列をコピーすると「‐」（U+2010）になる（IPAex で同じ字形を共有するため）。表示・印刷には影響しない | 現時点では対応不要。PDF から金額・番号をコピーして使う運用がないかを受入テストで確認する |
| 3 | 非同期起動の方法（P-05） | Spring Batch 6 では JobLauncher に代わり JobOperator を使用する。`@BatchTaskExecutor` を付けた TaskExecutor を定義すると、自動構成の JobOperator が非同期で実行し、実行IDを返してすぐに戻る | `BatchConfig`・`JobLaunchService` として実装。バッチ詳細設計 1章にクラス名を記載 |
| 4 | Reader のスコープ（P-05） | チャンク処理の Reader をシングルトンの Bean にすると、1回目の実行で読み終えた状態が残り、2回目以降は0件で「完了」となる | 請求締め（BAT-03）の Reader は `@StepScope` とし、実行ごとに対象得意先を取得する。バッチ詳細設計 4.1 に記載 |
| 5 | 存在しない実行IDの取得（P-05） | Spring Batch 6 の JDBC 実装は、存在しない実行IDの取得で null ではなく EmptyResultDataAccessException を送出する | `JobLaunchService.findProgress` で「該当なし」として扱い、画面は 404 とする |
| 6 | MyBatis のバージョン（P-01） | 選定時に想定した 4.0.x の後継として、Spring Boot 4.1 に対応した 4.1.0 が提供されていた | 4.1.0 を採用し、技術選定書を 1.2版に改訂 |
| 7 | 開発環境のポート | 開発者 PC に PostgreSQL がインストールされていると、5432 番ポートが競合し、PC 側の PostgreSQL に接続される | docker compose のホスト側ポートを 5433 とする（環境変数 DB_PORT で変更可）。開発環境構築手順書に記載 |
