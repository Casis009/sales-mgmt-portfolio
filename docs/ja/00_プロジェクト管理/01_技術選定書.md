## 1. 選定方針

1. **保守性・人材確保を優先する**：国内の業務システム開発で実績が多く、保守を引き継げる技術者が確保しやすい技術を選定する。
2. **サポート期間を重視する**：稼働予定（2027年4月）から最低2年以上、セキュリティパッチが提供される版を選定する。
3. **最新版より安定版**：メジャーリリース直後の版は避け、パッチが複数提供された版を採用する。
4. **ライセンス費用ゼロ**：顧客の予算制約により、OSS を基本とする。
5. **顧客の利用環境に合わせる**：利用端末は社内PC（Windows / Chrome）のみ（決定事項 D-04）。

## 2. 選定結果

### 2.1 アプリケーション

| 区分 | 採用技術 | バージョン | 選定理由 | 比較した代替案 |
|---|---|---|---|---|
| 言語 | Java | 21（LTS） | 国内業務システムで最も普及、ライブラリの対応実績が豊富 | Java 25（LTS）：対応ライブラリの実績を見て次期に検討 |
| フレームワーク | Spring Boot | 4.1.x（4.1.3） | 3.5系は2026年6月にOSSサポート終了。4.1系はパッチが蓄積済み | 4.2系：2026年11月リリース直後のため見送り |
| O/Rマッパー | MyBatis | mybatis-spring-boot-starter 4.1.0（Spring Boot 4.1 対応版。1.1版では 4.0.x としていた） | SQLを直接管理でき、帳票・集計など複雑なSQLに強い。国内SIでの採用実績が多い | Spring Data JPA：複雑な集計SQLの可読性・チューニング性で劣る |
| 画面 | Thymeleaf + Bootstrap 5 | — | サーバーサイドレンダリングで構成が単純。業務画面に十分 | React（SPA）：利用者15名の社内システムには過剰 |
| 認証・認可 | Spring Security | Boot 4.1 同梱版 | フォーム認証・ロールによる権限制御が標準で可能 | — |
| バッチ | Spring Batch | Boot 4.1 同梱版 | 月次締め・発注点チェックなど夜間バッチ、再実行・実行履歴管理が可能 | cron + シェル：再実行・履歴管理が弱い |
| 帳票 | JasperReports | 7.0.x（7.0.8。jasperreports ＋ jasperreports-pdf） | 請求書・発注書のPDF出力。帳票レイアウトをデザイナーで管理可能 | SVF：国内標準だが有償のため見送り |
| 日本語フォント | IPAexフォント | — | PDF埋め込み可能な無償フォント | — |
| DBマイグレーション | Flyway | Boot 4.1 対応版 | DDLをバージョン管理し、環境間の差異をなくす | Liquibase：XML/YAML記述が冗長 |
| ビルド | Maven | 3.9.x（3.9.16。Maven Wrapper で固定） | 国内現場で最も一般的、設定が明示的 | Gradle：柔軟だが現場の保守者の習熟度を考慮 |

### 2.2 データベース

| 採用技術 | バージョン | 選定理由 | 比較した代替案 |
|---|---|---|---|
| PostgreSQL | 17 | 無償、商用利用実績が豊富。データ量（受注明細 年間約6万行）に対して十分 | Oracle Database：有償のため見送り。ただし将来の移行を考慮し、PostgreSQL固有機能の使用は最小限とする |

### 2.3 テスト

| 区分 | 採用技術 | 用途 |
|---|---|---|
| 単体テスト | JUnit 5 / Mockito / AssertJ | クラス・メソッド単位の検証 |
| カバレッジ | JaCoCo | C0（命令網羅）・C1（分岐網羅）の計測 |
| 結合テスト | Testcontainers 2.0.5（PostgreSQL） | 本番と同じDBを使ったMapper・Service層の検証 |
| E2Eテスト | Playwright for Java | 総合テストの業務シナリオ自動化 |
| 性能テスト | Apache JMeter | 繁忙期（受注 80件/日）を想定した負荷検証 |
| セキュリティ | OWASP ZAP | 脆弱性診断（簡易） |
| 静的解析 | Checkstyle / SpotBugs | コーディング規約・バグパターンの検出 |

### 2.4 インフラ・運用

| 区分 | 採用技術 | 選定理由 |
|---|---|---|
| 本番環境 | Oracle Cloud Infrastructure（大阪リージョン） | 国内リージョン、無償枠で検証・本番相当の環境を構築可能 |
| コンテナ | Docker / Docker Compose | 環境差異をなくし、リリース・切り戻しを容易にする |
| Webサーバー | Nginx | リバースプロキシ、HTTPS終端（Let's Encrypt） |
| CI/CD | GitHub Actions | ソース管理と一体化、無償枠で十分 |
| コンテナレジストリ | GitHub Container Registry | 同上 |
| 監視 | Spring Boot Actuator + Prometheus + Grafana | アプリ・サーバーのメトリクス可視化、アラート通知 |
| ログ | Logback | 業務ログ・操作ログ・エラーログを分離して出力 |
