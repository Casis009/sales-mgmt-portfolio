> IPA「非機能要求グレード」の大項目（可用性／性能・拡張性／運用・保守性／移行性／セキュリティ／システム環境・エコロジー）に沿って整理する。
> 「根拠」は数値を決めた理由であり、ヒアリングシート（H-NN）・決定事項（D-NN）に対応する。

## 1. 前提となる業務量

| 項目 | 現在 | 5年後の想定 | 根拠 |
|---|---|---|---|
| 利用者数 | 15名 | 20名 | H-02 |
| 同時利用者数 | 最大15名 | 最大20名 | 全員が同時に利用する場合を想定 |
| 商品数 | 800 | 1,050 | H-04（年50増） |
| 取引先数 | 230 | 300 | H-05 |
| 受注件数 | 平均40件/日、繁忙期80件/日（年間 約12,000件） | 年間 約15,000件 | H-06 |
| 受注明細行数 | 年間 約60,000行（平均5行/件） | 5年累計 約350,000行 | H-07 |
| 発注件数 | 月60件（年間 約720件） | 年間 約900件 | H-08 |
| 請求件数 | 月200件（得意先数） | 月260件 | H-05 |

## 2. 可用性

| No | 項目 | 要件 | 根拠 |
|---|---|---|---|
| NF-01 | 運用時間 | 平日 8:00 ～ 19:00（オンライン）。夜間・休日は計画停止可 | H-24（利用 8:30～18:00 の前後30分～1時間） |
| NF-02 | 稼働率 | 運用時間内 99%以上（月あたりの停止 約2.4時間以内） | 停止時は電話・紙で業務継続が可能なため |
| NF-03 | 目標復旧時間（RTO） | 障害検知から4時間以内 | 半日以内に復旧すれば当日出荷に間に合うため |
| NF-04 | 目標復旧時点（RPO） | 前日夜間のバックアップ時点 | 当日分は受注FAX・納品書から再入力可能なため |
| NF-05 | 冗長化 | 行わない（シングル構成） | 予算制約。NF-02～04 を満たせば可 |

## 3. 性能・拡張性

| No | 項目 | 要件 | 根拠 |
|---|---|---|---|
| NF-06 | 画面応答時間（登録・更新・単票照会） | 3秒以内（90%） | 一般的な業務システムの目安 |
| NF-07 | 画面応答時間（一覧検索） | 5秒以内（90%）。1ページ50件のページング表示 | 同上 |
| NF-08 | 帳票出力時間 | 1件あたり5秒以内 | 請求書は月200件を連続出力するため |
| NF-09 | 請求締め処理時間 | 得意先260社分を5分以内 | 5年後の件数で経理担当が待てる時間 |
| NF-10 | 夜間バッチ処理時間 | 各10分以内 | 22:00 開始、バックアップ開始（2:00）までに完了 |
| NF-11 | データ保持期間 | 伝票データ・操作ログとも5年間はオンラインで保持 | 5年後の想定件数で NF-06～09 を満たすこと |
| NF-12 | 性能確認の条件 | 5年分相当のデータを投入した状態で、同時20ユーザーの負荷をかけて確認する | 総合テストで検証 |

## 4. 運用・保守性

| No | 項目 | 要件 | 根拠 |
|---|---|---|---|
| NF-13 | バックアップ | DB全体を毎日 2:00 に取得。日次7世代、月次12世代を保管 | NF-04 |
| NF-14 | バックアップからの復旧確認 | リリース前および年1回、復旧手順を実施して確認する | バックアップが使えることの保証 |
| NF-15 | 監視 | サービスの死活、CPU・メモリ・ディスク使用率、バッチの異常終了を監視し、異常時は開発担当へ通知する | NF-03 |
| NF-16 | ログ | アプリケーションログは90日、操作ログは5年保持する | 障害調査・内部統制 |
| NF-17 | メンテナンス | リリースは運用時間外に実施する。事前に3営業日前までに顧客へ通知する | NF-01 |
| NF-18 | 問合せ対応 | 平日 9:00 ～ 18:00、メールで受付 | 開発担当1名体制のため |

## 5. 移行性

| No | 項目 | 要件 | 根拠 |
|---|---|---|---|
| NF-19 | 移行対象 | 商品・倉庫・取引先・ユーザーの各マスタ、発注点、切替時点の在庫数 | H-22、D-12 |
| NF-20 | 移行対象外 | 過去の受注・発注・請求の履歴。受注残・発注残は顧客が手入力する | D-12 |
| NF-21 | 移行方式 | 一括移行。2027/3/31（水）の棚卸結果を初期在庫とし、2027/4/1（木）から新システムで運用を開始する | H-19、棚卸日と一致させ在庫差異をなくす |
| NF-22 | 移行リハーサル | 本番移行前に2回実施し、件数・在庫数量の一致を確認する | 移行ミスの防止 |
| NF-23 | 並行稼働 | 行わない。稼働後1か月は現行 Excel を参照用として保管する | 二重入力の負荷を避けるため |

## 6. セキュリティ

| No | 項目 | 要件 | 根拠 |
|---|---|---|---|
| NF-24 | 認証 | ログインID・パスワードによる認証。パスワードは8文字以上で英字・数字を含むこと | K-12 |
| NF-25 | アカウントロック | 5回連続で認証に失敗した場合はロックし、システム管理者が解除する | 不正ログイン対策 |
| NF-26 | セッション | 無操作30分でタイムアウトする | 離席時の不正操作対策 |
| NF-27 | 権限制御 | 5種類の権限により、利用できる画面・操作を制限する | D-14 |
| NF-28 | 通信の暗号化 | すべての通信を HTTPS（TLS 1.2 以上）とする | インターネット経由で利用するため |
| NF-29 | アクセス元制限 | 顧客拠点（本社・北九州倉庫）の固定IPアドレスからのみアクセス可能とする | 社外からの利用は対象外（D-04） |
| NF-30 | パスワードの保管 | ハッシュ化して保存する（平文・可逆暗号は不可） | 漏えい時の被害防止 |
| NF-31 | 操作ログ | 誰が・いつ・何を・どう変更したかを記録する。操作ログは画面から変更・削除できない | K-09, K-12 |
| NF-32 | 脆弱性対策 | SQLインジェクション、クロスサイトスクリプティング、CSRF への対策を行う。リリース前に脆弱性診断を実施する | IPA「安全なウェブサイトの作り方」 |

| No | 項目 | 要件 | 根拠 |
|---|---|---|---|
