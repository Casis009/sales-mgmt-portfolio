| 3 | 권한 체크(Controller·화면) | ○ | URL(명시적으로 허용한 URL 외 거부), Service(`@PreAuthorize`), 화면(역할별 메뉴). `AuthorizationIT`로 권한 매트릭스 각 행 확인 |

| 9 | 설계와 다른 구현 시 설계서 갱신 | ○ | 1.4대로 개정 |

### 1.3 지적 사항(리뷰·테스트에서 찾아 고친 것)

| No | 구분 | 내용 | 대응 |
|---|---|---|---|
| RV-01 | 설계 누락 | 트랜잭션 AOP와 조작 로그 AOP가 둘 다 최저 우선이라 순서가 보장되지 않음. 순서가 뒤집히면 업무가 롤백돼도 로그만 남음 | `TransactionConfig`로 순서 명시, 로그 등록을 `MANDATORY`로. 소프트웨어 구성 5장 No.8 추가 |
| RV-02 | 버그 | 세션 만료 URL `/login?timeout`의 값이 비어 있어 공백 제거 공통 처리로 null이 되고 E-013이 안 나옴 | `/login?timeout=1`로 변경(`LoginIT`에서 검출) |
| RV-03 | 버그 | 비밀번호를 비운 채 전송해도 실패 횟수가 늘어남 | 미입력은 인증 시도로 세지 않음(보안 설계 1장 No.9) |
| RV-04 | 버그 | MyBatis `javaType="long"`은 `java.lang.Long` 별칭이라 `long` 인수 record를 만들 수 없음 | 기본형 별칭 `_long`으로 |
| RV-05 | 버그 | 페이징 링크가 쿼리 문자열에서 만들어져 검색 조건이 빠지는 경우가 있음 | 요청 파라미터로 URL 조립(`PageUrls`) |
| RV-06 | 사양 명확화 | CSRF 토큰 없는 POST(세션 만료 후 전송)는 403이 아니라 세션 만료(E-013)로 처리됨 | 업무상 타당하므로 사양으로 채택, 보안 설계 2장 No.1에 추기 |
