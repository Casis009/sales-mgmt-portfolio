# 개발 환경 구축 절차서

> ※ 일본어 원본(정본): `docs/ja/04_製造/01_開発環境構築手順書.md` (1.0판, 2027/01/18)

> 개발자 PC(Windows 11)에 개발 환경을 만들어 빌드·테스트·기동까지 할 수 있게 하는 절차다. 유지보수를 넘겨받은 담당자가 이 문서만으로 같은 환경을 만드는 것이 목적이다.

## 1. 필요한 소프트웨어

| 소프트웨어 | 버전 | 용도 | 비고 |
|---|---|---|---|
| JDK | 21 | 빌드·실행 | Temurin 또는 Oracle JDK. `java -version`으로 21인지 확인 |
| Docker Desktop | 최신판 | 개발용 PostgreSQL, 결합 테스트(Testcontainers) | WSL 2 백엔드 |
| Git | 최신판 | 소스 관리 | `core.autocrlf`는 기본값 그대로(줄바꿈은 `.gitattributes`로 통일) |
| IDE | Eclipse(Spring Tools) 또는 IntelliJ IDEA Community | 개발 | 기술 선정서 2.5 |

Maven은 설치하지 않아도 된다. 저장소의 Maven Wrapper(`mvnw` / `mvnw.cmd`)가 처음 실행할 때 Maven 3.9.16을 자동으로 받는다.

## 2. 구성

| 항목 | 설정 |
|---|---|
| 개발용 DB | docker compose로 기동. 호스트 쪽 포트는 **5433**(PC에 설치된 PostgreSQL의 5432와 겹치지 않게. 환경 변수 `DB_PORT`로 변경 가능) |
| DB 사용자 | `hanbai_owner`(테이블 소유자, Flyway가 사용), `hanbai_app`(앱이 사용, DML만). 보안 설계 5장(NF-31) |
| 프로파일 | 지정 없으면 `dev`. 테스트는 `test`(Maven이 자동 지정), 서버는 환경 변수 `SPRING_PROFILES_ACTIVE`(`stg`/`prd`) |
| 테이블 | 앱 기동 때 Flyway가 `src/main/resources/db/migration`의 DDL을 적용 |

구성도는 정본 참조.

## 3. 구축 절차

### 3.1 저장소 받기
```bash
git clone https://github.com/Casis009/sales-mgmt-portfolio.git
cd sales-mgmt-portfolio
```

### 3.2 개발용 DB 기동
```bash
docker compose up -d --wait
docker compose ps        # hanbai-db가 healthy인지
```
처음 기동할 때 `docker/postgres/init/01_create_app_user.sh`가 실행돼 앱용 사용자가 만들어진다. DB를 처음부터 다시 만들려면 `docker compose down -v`로 데이터를 지운 뒤 다시 기동한다.

### 3.3 빌드와 테스트
```bash
./mvnw verify            # Windows 명령 프롬프트에서는 mvnw.cmd verify
```

| 실행되는 것 | 결과 확인 위치 |
|---|---|
| Checkstyle(코딩 규약) | 위반이 있으면 빌드 실패. `target/checkstyle-result.xml` |
| 단위 테스트(`*Test`) | `target/surefire-reports/` |
| 결합 테스트(`*IT`, Testcontainers) | `target/failsafe-reports/` |
| SpotBugs | 지적이 있으면 빌드 실패. `target/spotbugsXml.xml` |
| JaCoCo(커버리지) | `target/site/jacoco/index.html` |

결합 테스트는 Docker Desktop이 켜져 있어야 한다. 처음에는 컨테이너 이미지를 받느라 시간이 걸린다.

### 3.4 앱 기동
```bash
./mvnw spring-boot:run
```
기동 후 `http://localhost:8080/actuator/health`가 `{"status":"UP"}`를 돌려주는지 확인한다. 화면(로그인 등)은 구현 2단계부터 만든다.

## 4. 자주 나는 에러

| 증상 | 원인 | 대처 |
|---|---|---|
| 기동 때 「사용자 "hanbai_owner"의 password 인증 실패」(한국어·일본어 등 메시지) | PC에 설치된 PostgreSQL에 접속하고 있음 | docker compose 포트 확인(기본 5433). `DB_PORT`를 바꿨다면 앱 기동 때도 같은 값을 환경 변수로 전달 |
| 결합 테스트가 「Could not find a valid Docker environment」로 실패 | Docker Desktop이 꺼져 있음 | Docker Desktop을 켜고 다시 실행 |
| 결합 테스트 시작이 몇 분 멈춤 | Docker Desktop 기동 직후라 컨테이너 생성이 늦음 | 그대로 기다린다. 나아지지 않으면 Docker Desktop 재시작 |
| Checkstyle 「First sentence of Javadoc is missing an ending period」 | Javadoc 첫 문장이 「。」로 끝나지 않음 | 첫 문장을 「。」로 끝낸다 |
| `docker compose up` 뒤 권한 에러(permission denied for table …) | 초기화 스크립트가 돌기 전의 볼륨이 남아 있음 | `docker compose down -v`로 다시 만든다 |

## 5. 관련 파일

| 파일 | 내용 |
|---|---|
| `pom.xml` | 라이브러리·플러그인 버전(기술 검증 결과 보고서 3장에서 확정) |
| `docker-compose.yml`, `docker/postgres/init/` | 개발용 DB |
| `src/main/resources/application*.yml` | 공통·환경별 설정 |
| `src/main/resources/db/migration/` | Flyway DDL(V1 업무 테이블, V2 BATCH_*, V3 권한) |
| `config/checkstyle/`, `config/spotbugs/` | 정적 분석 설정 |
| `.github/workflows/ci.yml` | CI |
