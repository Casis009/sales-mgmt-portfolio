## 2. 입하 등록(ReceivingService.register)
권한: `hasRole('WAREHOUSE')`, 조작 로그: CREATE / SCR-304 / t_receiving

| No | 처리 | 에러 시 |
|---|---|---|
| 1 | 발주 헤더를 `FOR UPDATE`로 가져온다 | 없음: 시스템 에러 |
| 2 | 화면에서 받은 version과 비교 | E-020 |
| 3 | 상태가 「承認済(30)」 또는 「一部入荷(40)」인지 확인 | E-021 |
| 4 | 입하일이 발주일 이후이고 당일 이전인지 확인 | E-007 |
| 5 | 발주 명세를 가져와 입력된 명세와 맞춰 본다. 이번 입하 수가 0인 행은 제외 | — |
| 6 | 입하할 명세가 1행 이상인지 확인 | E-044 |
| 7 | 명세마다 「이번 입하 수 ≦ 발주 수량 − 입하 완료 수량」 확인(BR-26) | E-042 |
| 8 | 입하 번호 채번(RC, 입하일의 연월) | — |
| 9 | `StockService.receive` 호출(창고 = 발주의 입하 창고) | E-031 |
| 10 | 입하·입하 명세 등록 | — |
| 11 | 발주 명세의 입하 완료 수량에 이번 입하 수를 더한다 | — |
| 12 | 발주 헤더 갱신. 전 명세가 「입하 완료 수량 = 발주 수량」이면 「入荷完了(50)」, 아니면 「一部入荷(40)」. version + 1 | — |

## 3. 입하가 할당에 미치는 영향
입하에서는 현재고 수만 더하고 할당 수는 바꾸지 않는다. 유효 재고 수(현재고 수 − 할당 수)가 마이너스였다면 입하로 자동 해소된다. 수주별 「할당됨/미할당」은 관리하지 않으므로 입하 때 특정 수주에 재고를 배정하는 처리는 하지 않는다(출하 순서는 물류 담당이 출하 예정 목록의 납기순으로 판단).

## 4. 잔량 취소(PurchaseOrderService.closeRemaining)

| No | 처리 | 에러 시 |
|---|---|---|
| 1 | 발주 헤더를 `FOR UPDATE`로 가져와 version 비교 | E-020 |
| 2 | 상태가 「一部入荷(40)」인지 확인 | E-021 |
| 3 | 상태를 「入荷完了(50)」, 잔량 취소 플래그를 true로 갱신. version + 1 | — |

- 발주 명세의 발주 수량·입하 완료 수량은 바꾸지 않는다(처음 발주 수량을 기록으로 남김).
- 발주 잔량 집계는 상태 20·30·40이 대상이므로 잔량 취소 후 발주는 발주 잔량에 들어가지 않는다.
- 재고는 변하지 않는다.

## 5. 단위 테스트에서 확인할 주요 관점
- 전량 입하면 「入荷完了」, 일부 입하면 「一部入荷」가 될 것
- 이번 입하 수가 잔량과 같음(가능), 잔량 + 1(불가, E-042)
- 승인 대기·반려·취소 발주에는 입하 등록할 수 없을 것
- 입하 후 현재고 수가 늘고 할당 수는 그대로일 것. 입출고 이력의 변동 후 재고 수가 맞을 것
