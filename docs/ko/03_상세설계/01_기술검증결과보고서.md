## 1. 검증 목적
기술 선정서(1.1판)에서 채택한 기술 중 실적이 적은 조합과 이 프로젝트 고유의 조건을 구현 시작 전에 확인해 되돌림 위험을 낮춘다.

## 2. 검증 항목과 결과

검증은 초안이던 `poc/`가 아니라 실제 프로젝트(`pom.xml`, Flyway DDL) 위에 검증 테스트를 만들어 진행했다. 테이블 정의서대로 만든 실제 테이블로 확인할 수 있고, 검증 테스트를 CI에서 계속 돌려 라이브러리를 올릴 때 회귀를 잡을 수 있기 때문이다.

## 3. 채택 버전(확정)

`pom.xml`에 고정했다. 패치 버전을 올릴 때는 CI(이 문서의 검증 테스트 포함)가 성공하는 것을 조건으로 한다.

| 라이브러리 | 선정 시 계열 | 확정 버전 | 비고 |

| Spring Boot | 4.1.x | **4.1.3** | |

## 4. 문제가 나왔을 때의 대안

검증 결과 대안으로 바꾼 항목은 없다. P-03·P-04(GitHub Actions) 결과에 따라 아래 대안을 적용한다.

| No | 예상 문제 | 대안 | 설계 영향 | 적용 |
|---|---|---|---|---|
| P-01 | MyBatis 대응판이 Spring Boot 4.1에서 동작하지 않음 | Spring Boot를 4.0 계열 최신 패치로 낮춤 | 기술 선정서만 | 불필요 |
| P-02 | 일본어가 깨지거나 폰트를 내장할 수 없음 | ① 폰트 확장 설정 재검토 ② OpenPDF를 직접 써서 장표 출력 | ②면 장표 상세설계·공수 재검토 | 불필요 |
| P-03 | ARM에서 동작하지 않는 라이브러리가 있음 | OCI의 x86 인스턴스(AMD) 사용 | 시스템 구성도(인스턴스 종류)만 | 미정(P-03 실시 후) |
| P-04 | GitHub Actions에서 Testcontainers가 동작하지 않음 | CI에서는 워크플로의 services로 PostgreSQL을 띄워 접속 | 테스트 기반 설정만 | 미정(Actions 실행 후) |
| P-05 | 비동기 기동·실행 상황 조회가 생각대로 안 됨 | 청구 마감을 동기 처리로 | SCR-501 실행 상황 표시, 배치 상세설계 | 불필요 |

## 6. 검증에서 알게 된 사항과 대응

| No | 항목 | 알게 된 내용 | 대응 |
|---|---|---|---|
| 1 | 장표 굵은 글씨(P-02) | IPAex 고딕에는 굵은 서체가 없어서 `bold="true"`를 지정해도 굵게 표시되지 않음 | 장표(RPT-01·02)에서는 강조를 글자 크기·괘선으로 표현. 구현 6단계에서 장표를 만들 때 장표 설계서에 반영 |
| 2 | PDF 텍스트 복사(P-02) | 반각 하이픈 「-」은 PDF에서 문자열을 복사하면 「‐」(U+2010)가 됨(IPAex에서 같은 글리프를 공유). 표시·인쇄에는 영향 없음 | 지금은 대응 불필요. PDF에서 금액·번호를 복사해 쓰는 운용이 없는지 인수 테스트에서 확인 |
| 3 | 비동기 기동 방법(P-05) | Spring Batch 6에서는 JobLauncher 대신 JobOperator를 쓴다. `@BatchTaskExecutor`를 붙인 TaskExecutor를 정의하면 자동 구성된 JobOperator가 비동기로 실행하고 실행 ID를 바로 반환함 | `BatchConfig`·`JobLaunchService`로 구현. 배치 상세설계 1장에 클래스명 기재 |
| 4 | Reader 스코프(P-05) | 청크 처리 Reader를 싱글톤 빈으로 만들면 첫 실행에서 다 읽은 상태가 남아 두 번째부터 0건으로 「완료」가 됨 | 청구 마감(BAT-03)의 Reader는 `@StepScope`로 해서 실행마다 대상 거래처를 가져옴. 배치 상세설계 4.1에 기재 |
| 5 | 없는 실행 ID 조회(P-05) | Spring Batch 6 JDBC 구현은 없는 실행 ID를 조회하면 null이 아니라 EmptyResultDataAccessException을 던짐 | `JobLaunchService.findProgress`에서 「해당 없음」으로 처리하고 화면은 404 |
| 6 | MyBatis 버전(P-01) | 선정 때 예상한 4.0.x의 후속으로 Spring Boot 4.1 대응 4.1.0이 나와 있었음 | 4.1.0 채택, 기술 선정서를 1.2판으로 개정 |
| 7 | 개발 환경 포트 | 개발자 PC에 PostgreSQL이 설치돼 있으면 5432 포트가 겹쳐서 PC 쪽 PostgreSQL에 접속됨 | docker compose의 호스트 쪽 포트를 5433으로(환경 변수 DB_PORT로 변경 가능). 개발 환경 구축 절차서에 기재 |
