# 기술 검증 결과 보고서

> ※ 일본어 원본(정본): `docs/ja/03_詳細設計/01_技術検証結果報告書.md` (0.1판, 2026/12/28: 검증 실시 전)

> **현재 상태: 검증 미실시.** 검증용 코드(`poc/`)는 만들었지만 아직 실행하지 않았다. 「결과」 칸은 실행 후 채워서 1.0판으로 한다.
> 상세설계(02 이후)는 기술 선정서의 구성으로 문제없이 동작한다는 전제로 작성했다. 검증에서 문제가 나오면 4장의 대안으로 바꾸고 영향받는 설계서를 개정한다.

## 1. 검증 목적
기술 선정서(1.1판)에서 채택한 기술 중 실적이 적은 조합과 이 프로젝트 고유의 조건을 구현 시작 전에 확인해 되돌림 위험을 낮춘다.

| No | 검증 항목 | 확인 방법 | 합격 기준 | 결과 | 실시일 |

## 4. 문제가 나왔을 때의 대안

| No | 예상 문제 | 대안 | 설계 영향 |
|---|---|---|---|
| P-01 | MyBatis 대응판이 Spring Boot 4.1에서 동작하지 않음 | Spring Boot를 4.0 계열 최신 패치로 낮춤(4.0 계열은 대응판 제공됨) | 기술 선정서만 |
| P-02 | 일본어가 깨지거나 폰트를 내장할 수 없음 | ① 폰트 확장 설정 재검토 ② OpenPDF를 직접 써서 장표 출력 | ②면 장표 상세설계·공수 재검토 |
| P-03 | ARM에서 동작하지 않는 라이브러리가 있음 | OCI의 x86 인스턴스(AMD) 사용 | 시스템 구성도(인스턴스 종류)만 |
| P-04 | GitHub Actions에서 Testcontainers가 동작하지 않음 | CI에서는 워크플로의 services로 PostgreSQL을 띄워 접속 | 테스트 기반 설정만 |
| P-05 | 비동기 기동·실행 상황 조회가 생각대로 안 됨 | 청구 마감을 동기 처리(화면은 처리 완료까지 대기)로. 5년 후 건수에서도 수십 초 예상 | SCR-501 실행 상황 표시, 배치 상세설계 |
