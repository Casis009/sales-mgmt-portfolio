# 단위 테스트 관점 목록

> ※ 일본어 원본(정본): `docs/ja/03_詳細設計/07_単体テスト観点一覧.md` (1.0판, 2027/01/15)
> 이 문서는 「무엇을 확인하나(관점)」를 정한다. 구체적인 입력값·기대 결과는 단위 테스트 공정에서 「단위 테스트 사양서」로 만든다.
> 단위 테스트 대상은 클래스·메서드 단위의 동작이다. 화면 간·기능 간 연계는 통합 테스트에서 확인한다.

## 1. 공통 방침

| No | 항목 | 방침 |
|---|---|---|
| 1 | 대상 | Service, 계산 부품, Validator, Mapper. Controller는 입력 체크와 화면 전이 확인 |
| 2 | Service·계산 부품 | JUnit 5 + Mockito. Mapper·다른 Service를 목으로. 일시는 `Clock` 고정 |
| 3 | Mapper·집합 연산 SQL이 중심인 Service | Testcontainers(PostgreSQL)로 실제 SQL 실행. 목으로는 SQL 오류를 잡을 수 없으므로 |
| 4 | Controller | MockMvc. 권한(역할별 접근 가능 여부), 입력 체크, 에러 시 재표시 확인 |
| 5 | 커버리지 목표 | Service·계산 부품: 명령 커버리지(C0) 90% 이상, 분기 커버리지(C1) 80% 이상. 전체: C0 80% 이상 |
| 6 | 테스트 메서드명 | 일본어로 「조건_기대 결과」(개발 표준서) |

### 테스트 기법

| 기법 | 적용하는 곳 | 예 |
|---|---|---|
| 동치 분할(同値分割) | 입력값을 「유효」「무효」 그룹으로 나눠 그룹마다 대표값 선택 | 수량: 유효(1~999,999), 무효(0 이하, 1,000,000 이상, 숫자 아님) |
| 경계값 분석(境界値分析) | 유효와 무효의 경계 값을 반드시 확인 | 수량: 0, 1, 999,999, 1,000,000 |
| 디시전 테이블 | 여러 조건의 조합으로 결과가 바뀌는 처리 | 발주 상태 × 조작(8×8) |
| 상태 전이 테스트 | 상태를 가진 전표 | 수주: 수주 완료 → 일부 출하 → 출하 완료, 출하 취소에 의한 역방향 전이 |
