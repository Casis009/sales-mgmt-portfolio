# 보안 설계

> ※ 일본어 원본(정본): `docs/ja/03_詳細設計/04_セキュリティ設計.md` (1.2판, 2027/01/26: 2장 No.6 정적 파일은 세션 미사용, 3장 ③에 관리자가 없어지는 변경 금지 추가. 1.1판 2027/01/25: 1장 No.8 초기 관리자 생성·No.9 미입력 처리 추가, No.3 메시지 명기, 2장 No.1 타임아웃 URL·CSRF 토큰 없는 전송 처리 추기). 인증 시퀀스 그림은 원본 참조.
> 비기능 요건(NF-24~NF-32)을 어떤 장치로 실현할지 정한다. 위협 도출은 IPA 「安全なウェブサイトの作り方」 항목을 따른다.

## 1. 인증

| No | 항목 | 설계 | 대응 요건 |
|---|---|---|---|
| 1 | 방식 | Spring Security 폼 인증. 로그인 ID·비밀번호를 POST /login으로 받는다 | NF-24 |
| 2 | 비밀번호 보관 | BCrypt로 해시(스트레칭 횟수는 Spring Security 기본값). 평문·복호화 가능한 형식으로 저장하지 않는다 | NF-30 |
| 3 | 비밀번호 조건 | 8자 이상 64자 이하, 영문과 숫자를 각각 1자 이상. 로그인 ID와 같은 문자열 불가. 쓸 수 있는 문자는 반각 영숫자·기호만. 위반 시 메시지는 8자 미만·문자 종류가 E-015, 65자 이상이 E-002, 로그인 ID와 같으면 E-016(`PasswordPolicy`) | NF-24 |
| 4 | 초기 비밀번호 | 시스템 관리자가 설정. 첫 로그인 때 비밀번호 변경 화면으로 강제 이동하고 변경 전에는 다른 화면을 쓸 수 없다 | NF-24 |
| 5 | 계정 잠금 | 인증 실패마다 실패 횟수를 1 더하고 5회가 되면 잠근다. 인증 성공 시 0으로. 잠금 해제는 시스템 관리자 | NF-25 |
| 6 | 인증 에러 표시 | 로그인 ID 오류·비밀번호 오류·무효 사용자는 같은 메시지(E-010) | 정보 유출 대책 |
| 7 | 로그아웃 | 세션을 무효화하고 쿠키 삭제 | — |
| 8 | 초기 관리자 생성 | 사용자가 한 명도 없는 상태로 기동한 경우에만 초기 시스템 관리자(역할 ADMIN, 비밀번호 변경 요구 있음)를 만든다. 비밀번호는 환경 변수 `HANBAI_INITIAL_ADMIN_PASSWORD`로 넘기고 소스 코드·저장소에 넣지 않는다(개발 환경만 application-dev.yml에 기본값). 미설정이면 만들지 않는다. 이후 사용자는 화면(SCR-012)에서 등록 | NF-24 |
| 9 | 미입력 | 로그인 ID·비밀번호 미입력은 E-001. 인증 시도가 아니므로 실패 횟수에 넣지 않고 조작 로그에도 남기지 않는다 | — |

인증 흐름: POST /login → 사용자 조회 → (없음·무효: E-010 / 잠금: E-011 / 비밀번호 불일치: 실패 횟수 +1(5회면 잠금), 조작 로그 LOGIN_FAILURE, E-010 / 성공: 실패 횟수 0, 최종 로그인 일시, 조작 로그 LOGIN, 세션 ID 재발급 후 메뉴로 리다이렉트)

## 2. 세션 관리

| No | 항목 | 설계 | 대응 요건 |
|---|---|---|---|
| 1 | 타임아웃 | 무조작 30분. 타임아웃 후 조작은 로그인 화면(`/login?timeout=1`)으로 이동(E-013). 타임아웃 후 입력 화면에서 전송한 경우(세션에 CSRF 토큰이 없는 POST)도 처리하지 않고 같은 로그인 화면으로 이동 | NF-26 |
| 2 | 세션 고정 공격 대책 | 로그인 성공 시 세션 ID 재발급 | NF-32 |
| 3 | 쿠키 속성 | `Secure`, `HttpOnly`, `SameSite=Lax` | NF-32 |
| 4 | 동시 로그인 | 제한하지 않음(같은 사용자가 여러 탭·PC로 쓸 수 있으므로) | — |
| 5 | 세션에 두는 정보 | 로그인 사용자 정보, 이중 전송 방지 토큰, 목록 검색 조건만. 업무 데이터는 두지 않는다 | — |
| 6 | 정적 파일(`/css/**`, `/js/**`) | 화면과 다른 보안 필터로 배포하고 세션을 참조·생성하지 않는다. 앱 재시작·세션 만료 후 사라진 세션 ID로 요청된 정적 파일까지 세션 만료로 로그인 화면에 보내져 CSS가 적용되지 않는 화면이 되는 것을 막는다. 보안 헤더는 화면과 같이 붙인다 | NF-26 |

## 3. 인가(권한 제어)
권한 매트릭스 내용을 아래 3단계로 제어한다.

| 단계 | 제어 내용 | 구현 | 예 |
|---|---|---|---|
| ① URL | 화면을 열 수 있는가 | `SecurityConfig`에서 URL 패턴과 역할을 대응 | `/billing/closings/**`는 ACCOUNTING만 |
| ② 조작 | 갱신 처리를 실행할 수 있는가 | Service 메서드에 `@PreAuthorize` | `ShipmentService.register`는 WAREHOUSE만 |
| ③ 데이터 | 대상 데이터에 대해 실행할 수 있는가 | Service의 업무 체크 | 자기가 신청한 발주는 승인 불가(E-040). 자기 자신 무효화·ADMIN 삭제(E-018), 유효한 시스템 관리자가 0명이 되는 변경(E-019) 불가 |

- 화면에서는 권한 없는 메뉴·버튼을 보여 주지 않는다(Thymeleaf의 Spring Security 연계 기능 사용). 이건 조작 편의를 위한 것이지 ①②를 생략할 이유가 되지 않는다.
- ①에서 「조회만 가능」인 역할(시스템 관리자 등)이 갱신용 URL에 POST하면 ②에서 거부한다.
- 권한 에러는 E-012(HTTP 403)로 하고 WARN 로그에 사용자·URL을 출력한다.

### URL과 역할 대응(발췌)

| URL 패턴 | 허용 역할 |
|---|---|
| `/login`, `/css/**`, `/js/**` | 전원(미인증 포함) |
| `/menu`, `/password`, `/stock/stocks/**`, `/master/*`(목록) | 인증된 전원 |
| `/admin/**` | ADMIN |
| `/stock/adjustments/**`, `/stock/transfers/**` | WAREHOUSE |
| `/stock/movements/**`, `/stock/stocktakings/**`, `/purchase/reorder-alerts/**`, `/sales/shipment-plans/**` | WAREHOUSE, ADMIN |
| `/purchase/orders/**` | WAREHOUSE, APPROVER, ADMIN |
| `/sales/orders/**` | SALES, WAREHOUSE, ACCOUNTING, ADMIN |
| `/billing/closings/**` | ACCOUNTING |
| `/billing/invoices/**` | ACCOUNTING, SALES, ADMIN |
| 그 외 | 거부(명시적으로 허용한 URL만 접근 가능) |

## 4. 취약점 대책

| No | 위협 | 대책 | 확인 방법 |
|---|---|---|---|
| 1 | SQL 인젝션 | MyBatis 바인드 변수(`#{}`)만 사용. `${}`는 사용 금지로 하고 정적 검사(grep 검사를 CI에 넣음)로 검출. 정렬 순서처럼 동적으로 바꾸는 부분은 Enum에서 고정 문자열로 변환 | 코드 리뷰, CI, 취약점 진단 |
| 2 | 크로스 사이트 스크립팅(XSS) | Thymeleaf의 `th:text`(자동 이스케이프) 사용. `th:utext` 사용 금지. JavaScript에 값을 넘길 때는 Thymeleaf 인라인 기능 사용 | 위와 같음 |
| 3 | CSRF | Spring Security의 CSRF 대책을 켠다(POST에 토큰). 상태를 바꾸는 조작을 GET으로 하지 않는다 | 취약점 진단 |
| 4 | 세션 하이재킹 | HTTPS만, 쿠키 `Secure`·`HttpOnly`, 세션 ID 재발급 | 위와 같음 |
| 5 | 클릭재킹 | `X-Frame-Options: DENY` | 위와 같음 |
| 6 | 파라미터 변조 | 금액·상태·등록자 등은 화면에서 받지 않고 서버에서 계산·설정. Form에는 입력 항목만 정의. ID를 지정한 조작은 ③ 데이터 권한 체크 | 코드 리뷰, 통합 테스트 |
| 7 | 디렉터리 트래버설, OS 명령 인젝션 | 사용자 입력을 파일 경로·명령에 쓰지 않는다(장표는 고정 정의 파일만 사용) | 코드 리뷰 |
| 8 | CSV 인젝션 | CSV 출력(F-405)에서 값이 `=` `+` `-` `@`로 시작하면 앞에 `'`를 붙인다 | 단위 테스트 |
| 9 | 정보 노출 | 에러 화면에 스택 트레이스·SQL을 표시하지 않는다. HTTP 헤더에서 서버 버전 정보를 지운다 | 취약점 진단 |
| 10 | 알려진 취약점이 있는 라이브러리 | CI에서 의존 라이브러리 취약점 검사 실행. Spring Boot 패치 릴리스를 따라간다 | CI |

## 5. 통신·인프라

| No | 항목 | 설계 | 대응 요건 |
|---|---|---|---|
| 1 | 통신 암호화 | Nginx에서 TLS 1.2 이상만 허용. HTTP(80)는 HTTPS로 리다이렉트. HSTS 설정 | NF-28 |
| 2 | 접속원 제한 | OCI 시큐리티 리스트에서 443 포트 송신원을 고객 거점 고정 IP로 한정 | NF-29 |
| 3 | 관리용 엔드포인트 | Spring Boot Actuator는 헬스 체크와 메트릭만 켜고 외부(Nginx 경유)에서는 접근할 수 없게 한다 | NF-32 |
| 4 | DB 접속 | 애플리케이션에서만 접속 가능(Docker 내부 네트워크). DB 포트를 외부에 열지 않는다 | NF-32 |
| 5 | DB 사용자 권한 | 애플리케이션용 사용자에게는 DML만 허용(DDL 불가). 조작 로그 테이블에는 INSERT와 SELECT만. DDL을 실행하는 Flyway용 사용자는 따로 둔다 | NF-31 |
| 6 | 비밀 정보 관리 | DB 비밀번호 등은 환경 변수로 넘기고 소스 코드·리포지토리에 넣지 않는다. GitHub Actions에서는 Secrets 사용 | — |
| 7 | 서버 로그인 | SSH는 공개키 인증만. 송신원을 개발 담당 고정 IP로 한정 | — |

## 6. 감사

|---|---|---|---|

## 7. 포트폴리오 공개 환경에서의 취급(참고)
이 설계는 고객용 운영 환경을 전제로 한다. 포트폴리오로 인터넷에 공개하는 데모 환경에서는 아래를 바꾼다. 바꾸는 점은 환경별 설정으로 전환하고 설계·소스 코드는 공통으로 한다.

| 항목 | 운영 환경 | 데모 환경 |
|---|---|---|
| 접속원 제한(NF-29) | 고객 거점 고정 IP만 | 제한 없음 |
| 사용자 | 고객 사용자 | 열람용 데모 사용자(역할별). 비밀번호 변경·사용자 관리 불가 |
| 데이터 | 고객 업무 데이터 | 가상 샘플 데이터. 매일 밤 초기화 |
