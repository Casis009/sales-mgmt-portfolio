## 1. 배경

고객은 현재 수주, 재고, 발주, 청구 업무를 Excel·종이·FAX로 각각 따로 관리하고 있다.
사업이 커지면서 취급 상품 수(약 800 SKU)와 거래처 수가 늘었고, 아래 문제가 드러났다.

- 같은 정보를 여러 Excel 파일에 옮겨 적고 있어 입력 실수와 이중 입력이 잦다
- 재고 수량을 실시간으로 알 수 없어 결품으로 주문을 놓치거나 과잉 재고가 생긴다
- 발주 시점이 담당자의 경험에 좌우된다(속인화)
- 누가 언제 데이터를 바꿨는지 추적할 수 없다

## 2. 목적

1. 수주·출하·재고·발주·청구 정보를 한곳에서 관리해 이중 입력을 없앤다
2. 재고 수량을 실시간으로 보여 줘 결품과 과잉 재고를 줄인다
3. 발주점 기반 발주 알림으로 발주 업무의 속인화를 해소한다
4. 조작 로그와 권한 관리로 데이터 신뢰성과 내부통제를 확보한다

## 3. 대상 범위(첫 미팅 시점의 가정)

| 구분 | 대상 | 대상 외(2차 개발 이후 검토) |
|---|---|---|
| 공통 | 로그인, 권한 관리, 조작 로그 | SSO, 비밀번호 재설정 메일 |
| 마스터 | 상품, 창고, 거래처(매출처·매입처) | 단가 이력, 세트 상품 |
| 재고 | 입출고, 재고 조회, 재고 실사 | 로트·유효기한 관리, 로케이션 관리 |
| 구매 | 발주 → 승인 → 입하(재고 자동 가산) | 지급, 매입채무 관리 |
| 판매 | 수주 → 출하(재고 자동 감산) → 청구서 PDF | 견적, 입금 대조, 매출채권 관리 |
| 배치 | 발주점 알림, 월별 재고 집계 | 회계 시스템 연동 |

> 대상 범위는 요건정의 공정에서 고객과 합의해 확정한다.
