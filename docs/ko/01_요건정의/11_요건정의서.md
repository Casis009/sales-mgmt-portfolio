## 1. 개요

### 1.1 배경
주식회사 히카리 조명상사(이하 「고객」)는 수주·재고·발주·청구 업무를 Excel·종이·FAX로 각각 관리하고 있다. 취급 상품 수(약 800 SKU)와 거래처 수가 늘면서 이중 입력에 따른 실수, 재고 수 불일치, 발주 업무의 속인화, 청구서 작성 부담이 과제가 되었다.

### 1.2 목적과 달성 기준

| No | 목적 | 달성 기준 |
|---|---|---|
| 1 | 정보 일원화로 이중 입력을 없앤다 | 수주 정보 입력이 한 번으로 끝나고 출하·청구까지 재입력이 없을 것 |
| 2 | 재고 수를 실시간으로 보여 준다 | 출하·입하 등록 직후 재고 조회에 반영될 것. 월별 실사 차이 품목 수가 현행(20~30개)의 절반 이하가 될 것 |
| 3 | 발주 업무의 속인화를 해소한다 | 발주 알림 목록을 바탕으로 물류 담당 누구나 발주 등록을 할 수 있을 것 |
| 4 | 청구서 작성 부담을 줄인다 | 청구서 작성 작업을 현행 약 3일에서 반나절 이내로 줄일 것 |
| 5 | 데이터 신뢰성과 내부통제를 확보한다 | 모든 등록·변경·승인에 대해 조작자와 일시를 추적할 수 있을 것 |

### 1.3 시스템화 방침
- 「재고」를 중심으로 구매(발주~입하)와 판매(수주~출하~청구)를 잇는다.
- 재고 증감은 모두 전표 등록(입하·출하·조정·이동·실사)을 통해서만 하고 입출고 이력에 기록한다. 재고 수를 화면에서 직접 고쳐 쓰는 기능은 두지 않는다.
- 돈이 오가는 업무(지급, 입금 대조)와 회계 시스템 연동은 대상 외로 하고 2차 개발에서 검토한다.

## 2. 대상 범위

### 2.1 대상 업무

| 업무 | 대상 | 대상 외 |
|---|---|---|
| 공통 | 인증, 권한 관리, 조작 로그 | SSO, 비밀번호 재설정 메일 |
| 마스터 관리 | 상품, 창고, 거래처, 발주점 | 매출처별 단가, 단가 이력, 세트 상품 |
| 재고 관리 | 재고 조회, 입출고 이력, 재고 조정, 창고 간 이동, 실사 | 로트·유효기한 관리, 로케이션(선반 번호) 관리 |
| 구매 관리 | 발주, 승인, 발주서 출력, 입하 | 매입 계상, 지급, 매입채무 관리 |
| 판매 관리 | 수주, 출하, 출하 취소(입력 오류 정정) | 견적, 반품, 출하 전표·납품서 출력 |
| 청구 관리 | 청구 마감, 청구서 출력 | 입금 대조, 매출채권 관리, 이월 금액 표시 |

### 2.2 사용자와 권한

| 권한 | 대상자(가정) | 주요 업무 |
|---|---|---|
| 영업 담당 | 영업부 8명 | 수주 등록, 재고 조회, 거래처 관리 |
| 물류 담당 | 물류과 5명 | 출하, 입하, 발주 등록, 재고 조정, 실사 |
| 경리 담당 | 총무경리과 2명 | 청구 마감, 청구서 출력 |
| 승인자 | 다나카 부장, 스즈키 과장 | 발주 승인 |
| 시스템 관리자 | 고객 측 1명, 개발 담당 | 사용자 관리, 마스터 관리, 조작 로그 조회 |

※ 한 사용자에게 여러 권한을 줄 수 있다(D-14).

### 2.3 시스템화 범위도
일본어 원본의 그림 참조. 매입처 →(납품)→ [구매 관리 → 재고 관리 ← 판매 관리 → 청구 관리] →(청구서 PDF)→ 매출처. 회계 소프트웨어 연동은 대상 외(직접 입력).

## 3. 업무 요건
신규 업무 흐름은 「별지 07 신규 업무 흐름도(To-Be)」와 같다. 주요 업무 규칙은 아래와 같다.

### 3.1 재고

| No | 업무 규칙 | 근거 |
|---|---|---|
| BR-01 | 재고는 「상품 × 창고」별로 현재고 수와 할당 수를 관리한다 | K-07 |
| BR-02 | 유효 재고 수 = 현재고 수 − 할당 수. 유효 재고 수는 마이너스가 될 수 있다(재고 부족을 뜻함) | D-15 |
| BR-03 | 현재고 수는 0 미만이 되지 않는다. 현재고 수를 넘는 출하·이동·조정(감소)은 등록할 수 없다 | K-04 |
| BR-04 | 재고 증감은 반드시 입출고 이력에 기록한다 | K-09 |
| BR-05 | 실사 진행 중에는 대상 창고에 대한 입하·출하·재고 조정·창고 간 이동을 등록할 수 없다 | D-18 |
| BR-06 | 실사 확정 시 실사 수량과 장부 재고 수의 차이를 재고에 반영한다. 차이가 있는 명세는 이유 입력 필수 | K-09 |

### 3.2 판매

| No | 업무 규칙 | 근거 |
|---|---|---|
| BR-11 | 수주는 출하 창고를 하나 지정해 등록한다 | H-03 |
| BR-12 | 수주 등록 시 수주 수량을 할당 수에 더한다. 유효 재고 수가 부족하면 경고를 표시하지만 등록할 수 있다 | D-15 |
| BR-13 | 단가는 상품 마스터의 표준 판매 단가를 초기 표시하고 수주마다 바꿀 수 있다 | D-16 |
| BR-14 | 수주 한 건을 여러 번에 나눠 출하할 수 있다. 수주 명세별로 출하 완료 수량을 관리한다 | D-09 |
| BR-15 | 출하 등록 시 현재고 수와 할당 수에서 출하 수량을 뺀다 | K-04 |
| BR-16 | 수주 변경·취소는 미출하일 때만 가능하다. 일부 출하된 수주는 잔량 취소(수주 잔량 종결)만 가능하다 | D-09 |
| BR-17 | 출하 취소는 미청구 출하에 한해 가능하다. 취소 시 현재고 수·할당 수·수주 명세의 출하 완료 수량을 출하 전 상태로 되돌린다. 잔량 취소를 한 수주의 출하는 취소할 수 없다 | D-25(CR-01) |

### 3.3 구매

| No | 업무 규칙 | 근거 |
|---|---|---|
| BR-21 | 발주는 입하 창고를 하나 지정해 등록한다 | D-13 |
| BR-22 | 발주는 승인자의 승인이 필수다. 승인자는 신청자 본인이 아니어야 한다 | D-11 |
| BR-23 | 승인자는 반려할 수 있다. 반려 시 이유 입력 필수 | D-11 |
| BR-24 | 발주서는 승인된 발주만 출력할 수 있다 | K-06 |
| BR-25 | 발주 한 건을 여러 번에 나눠 입하할 수 있다. 발주 명세별로 입하 완료 수량을 관리한다 | D-09 |
| BR-26 | 입하 수량 합계는 발주 수량을 넘을 수 없다 | K-14 |
| BR-27 | 「유효 재고 수 + 발주 잔량 ≦ 발주점」이 된 상품을 매일 야간에 발주 알림으로 추출한다 | D-13 |

### 3.4 청구

| No | 업무 규칙 | 근거 |
|---|---|---|
| BR-31 | 청구는 출하 실적을 바탕으로 만든다(출하 기준) | K-10 |
| BR-32 | 마감일은 매출처별로 설정한다 | D-07 |
| BR-33 | 청구 마감에서는 마감 기간 내(지난 마감일 다음 날~이번 마감일)의 미청구 출하를 매출처별로 집계한다 | D-07 |
| BR-34 | 소비세는 청구서 단위로 세율별 대가를 합계해 세율을 곱하고 1엔 미만은 버린다 | D-08 |
| BR-35 | 청구서에는 적격청구서 기재 사항(발행자 명칭과 등록번호, 거래 연월일, 거래 내용, 세율별 대가와 적용 세율, 세율별 소비세액, 수신인)을 기재한다 | Q-09 |
| BR-36 | 발행된 청구는 취소할 수 없다. 미발행 청구는 취소하고 다시 마감 처리할 수 있다 | K-11 |
