# 권한 매트릭스

> ※ 일본어 원본(정본): `docs/ja/02_基本設計/13_権限マトリクス.md` (1.0판, 2026/12/18)
> ○ = 가능, — = 불가. 여러 역할을 가진 사용자는 어느 한 역할에서 「○」면 조작할 수 있다.

## 1. 방침

| No | 방침 | 이유 |
|---|---|---|
| 1 | 재고 수량을 바꾸는 조작(출하·입하·조정·이동·실사)은 물류 담당만 | 현물을 다루는 담당자만 재고를 움직일 수 있게(D-14) |
| 2 | 발주의 「신청」과 「승인」은 다른 사용자가 한다 | 상호 견제(BR-22). 같은 사용자가 두 역할을 다 가져도 자기 신청은 승인할 수 없다 |
| 3 | 시스템 관리자는 업무 데이터(전표)를 등록·변경할 수 없다 | 관리자 권한에 의한 부정·오조작 방지. 전 화면 조회는 가능 |
| 4 | 화면을 여는 것과 버튼을 누르는 것은 따로 제어한다 | 조회는 되지만 갱신은 안 되는 사용자가 있으므로 |

## 4. 구현 방침

| No | 내용 |
|---|---|
| 1 | URL 단위 제어(화면을 열 수 있는가)와 조작 단위 제어(버튼·갱신 처리)를 모두 서버 쪽에서 한다 |
| 2 | 화면에서는 권한 없는 버튼·메뉴를 보여 주지 않는다. 다만 이건 사용 편의를 위한 것이고 보안은 서버 쪽 제어로 담보한다 |
| 3 | 「자기 신청은 승인할 수 없다」처럼 데이터 내용에 따른 제어는 업무 로직(Service)에서 한다 |
