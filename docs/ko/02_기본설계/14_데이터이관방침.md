# 데이터 이관 방침

> ※ 일본어 원본(정본): `docs/ja/02_基本設計/14_データ移行方針.md` (1.0판, 2026/12/21)
> 이 문서는 이관 방침을 정한다. 작업 절차·체제·일정 상세는 이관·릴리스 공정에서 「이관 계획서」로 만든다.

## 1. 기본 방침

| No | 방침 | 근거 |
|---|---|---|
| 1 | 일괄 이관. 2027/3/31(수) 실사 결과를 초기 재고로 하고 2027/4/1(목)부터 가동 | NF-21 |
| 2 | 이관하는 것은 마스터와 초기 재고뿐. 과거 전표는 이관하지 않는다 | NF-19, NF-20, D-12 |
| 3 | 현행 Excel을 직접 읽지 않고 정해진 CSV 형식으로 바꾼 뒤 투입한다 | Excel 양식이 담당자마다 달라 기계적으로 읽을 수 없으므로 |
| 4 | 투입은 이관 도구(이 시스템과 별개의 실행 프로그램)로 하고, 체크에서 에러가 1건이라도 있으면 전건 투입하지 않는다 | 어중간한 상태의 데이터를 남기지 않기 위해 |
| 5 | 초기 재고는 입출고 이력에 「이관」으로 기록한다 | 가동 후 재고 수를 이력으로 설명할 수 있게(BR-04) |
| 6 | 실제 이관 전에 검증 환경에서 리허설을 2회 한다 | NF-22 |

| No | 대상 | 이관처 테이블 | 건수(개산) | 원본 | 데이터 작성 | 투입 방법 |
|---|---|---|---|---|---|---|
| 1 | 자사 정보·소비세율 | m_company, m_tax_rate | 3 | 히어링 결과 | 개발 담당 | SQL(초기 데이터) |
| 2 | 창고 | m_warehouse | 2 | 히어링 결과 | 개발 담당 | SQL(초기 데이터) |
| 3 | 사용자·역할 | m_user, m_user_role | 16 | T-09 목록 | 개발 담당 | 화면에서 등록(초기 비밀번호 설정) |
| 4 | 거래처 | m_partner | 230 | 수주대장.xlsx, 발주서.xlsx, T-08 목록 | 고객(영업부·총무경리과) | CSV 투입 |

| 6 | 발주점·표준 발주 수량 | m_product_warehouse | 최대 1,600 | 새로 작성 | 고객(야마모토 주임) | CSV 투입 |
| 7 | 초기 재고 | t_stock, t_stock_movement | 최대 1,600 | 2027/3/31 실사 결과 | 고객(물류과) | CSV 투입 |
| 8 | 수주 잔량·발주 잔량 | t_sales_order 외 | 수십 건 | 수주대장, 발주서 | 고객 | 가동 첫날 화면에서 입력 |

투입 순서: 1 → 2 → 3 → 4 → 5 → 6 → 7(참조되는 마스터를 먼저)

## 3. CSV 사양(공통)
- 문자 코드: UTF-8(BOM 포함). Excel의 「CSV UTF-8」로 저장한 파일을 그대로 쓸 수 있다.
- 쉼표 구분, 1행은 항목명(헤더).
- 항목명과 입력 예를 적은 Excel 템플릿을 개발 담당이 제공한다.

| CSV | 항목 |
|---|---|
| 거래처 | 거래처 코드, 거래처명, 가나, 매출처 플래그, 매입처 플래그, 우편번호, 주소, 전화번호, FAX 번호, 담당자명, 마감일, 지급 월 구분, 지급일 |
| 상품 | 상품 코드, 품명, 형번, 단위, 표준 판매 단가, 표준 매입 단가, 세 구분, 주 매입처 코드 |
| 발주점 | 상품 코드, 창고 코드, 발주점, 표준 발주 수량 |
| 초기 재고 | 상품 코드, 창고 코드, 수량 |

## 4. 투입 시 체크

| No | 체크 | 예 |
|---|---|---|
| 1 | 필수·형·자릿수 | 상품 코드가 비어 있음, 단가에 문자가 있음 |
| 2 | 파일 안 중복 | 같은 상품 코드가 2행 |
| 3 | 코드 값 | 세 구분이 1·2가 아님, 마감일이 1~28·99가 아님 |
| 4 | 참조처 존재 | 주 매입처 코드가 거래처에 없음, 창고 코드가 없음 |
| 5 | 업무 규칙 | 매출처 플래그가 ON인데 마감일이 비어 있음, 수량이 마이너스 |

에러는 「행 번호·항목명·에러 내용」을 목록(CSV)으로 출력하고 고객이 고쳐서 다시 제출한다.

## 5. 이관 결과 검증

| No | 검증 내용 | 방법 | 실시자 |
|---|---|---|---|
| 1 | 건수 일치 | CSV 행 수와 투입 후 테이블 건수 비교 | 개발 담당 |
| 2 | 수량 합계 일치 | 초기 재고 CSV 수량 합계, t_stock 현재고 수 합계, 입출고 이력(이관) 증감 수 합계 비교 | 개발 담당 |
| 3 | 내용 확인 | 상품·거래처를 각 20건 뽑아 화면 표시와 현행 Excel을 눈으로 비교 | 고객 |
| 4 | 재고 확인 | 재고 조회 화면에서 실사 결과 수량과 일치하는지 전 창고 합계와 추출 20건으로 확인 | 고객(물류과) |
| 5 | 업무 확인 | 수주 등록 → 출하 등록 → 재고 조회를 1건 해 보고 재고가 맞게 증감하는지 확인 | 고객·개발 담당 |

## 6. 일정(개요)

| 시기 | 내용 |
|---|---|
| 2027년 2월 초 | CSV 템플릿 제공, 마스터 데이터 작성 의뢰 |
| 2027년 2월 말 | 이관 리허설 1회차(2월 말 실사 결과 사용). 에러 내용을 고객에게 피드백 |
| 2027년 3월 중순 | 이관 리허설 2회차. 실제와 같은 절차·시간으로 하고 소요 시간 측정 |
| 2027/3/31(수) 영업 종료 후 | 실사, 초기 재고 CSV 작성 |
| 2027/3/31(수) 밤 | 실제 이관, 검증, 이관 판정 |
| 2027/4/1(목) | 가동 개시. 수주 잔량·발주 잔량을 화면에서 입력 |

## 7. 이관 실패 시 대응

| 상황 | 대응 |
|---|---|
| 3/31 밤 이관 판정에서 문제를 해소하지 못함 | 가동을 연기하고 4/1은 현행 Excel로 업무. 원인을 해소한 뒤 다음 월말(4/30) 실사 결과로 다시 이관 |
| 가동 후 이관 데이터 오류 발견 | 마스터는 화면에서 수정. 재고 수량은 재고 조정(이유: 이관 데이터 오류)으로 고치고 이력을 남긴다 |
