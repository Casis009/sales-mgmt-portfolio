## 3. 회의 내용

### 3.1 변경 요구 CR-01: 출하 취소 기능 추가

| 항목 | 내용 |
|---|---|
| 발생 경위 | 출하 등록 화면을 설계하다가 「출하 수량이나 출하할 수주를 잘못 등록했을 때 고칠 수단이 없다」는 것을 알게 됐다. 요건정의에서 반품은 대상 외로 했지만(D-10) 입력 오류 정정은 반품과 별개이며, 요건정의에서의 고려 누락이다 |
| 대응하지 않을 때의 영향 | 잘못된 출하가 그대로 청구에 들어간다. 재고 조정으로 재고 수는 되돌릴 수 있지만 수주의 출하 완료 수량과 청구 금액은 고칠 수 없다 |
| 변경 내용 | 미청구 출하에 한해 출하를 취소할 수 있는 기능(F-406) 추가. 취소 시 재고·할당·수주의 출하 완료 수량을 출하 전 상태로 되돌린다 |
| 제한 사항 | 청구 마감된 출하는 취소 불가(먼저 청구 마감 취소 필요. 발행된 청구는 취소 불가). 잔량 취소를 한 수주의 출하, 실사 중인 창고의 출하는 취소 불가 |
| 영향 범위 | 화면: SCR-403(수주 상세)에 버튼 추가. 테이블: 변경 없음(출하 상태·입출고 구분은 정의돼 있음). 설계서: 요건정의서, 기능 목록, 화면 목록, 권한 매트릭스, 메시지 목록 |
| 공수·일정 | 설계·구현·테스트로 약 3인일 증가. 구현 공정 예비일로 흡수할 수 있어 가동일 영향 없음 |
| 우선순위 | Should(일정이 빠듯하면 가동 후 이른 시기에 추가 릴리스) |

- 야마모토 주임: "입력 실수는 반드시 생기니 꼭 넣어 달라."
- 다나카 부장이 승인. → D-25

### 3.2 기본설계서 리뷰

| No | 지적자 | 대상 | 지적·질문 | 대응 |
|---|---|---|---|---|
| R-05 | 야마모토 주임 | SCR-404 출하 예정 목록 | 창고에 PC가 1대뿐이라 목록을 인쇄해서 피킹에 쓰고 싶다 | 인쇄용 레이아웃(헤더·메뉴 제외, 체크란 추가)을 준비한다. 장표(PDF)는 추가하지 않는다(D-26) |
| R-06 | 야마모토 주임 | SCR-212 실사 입력 | 800개 품목의 실사 수량을 화면에서 하나씩 넣기 힘들다. Excel에서 가져올 수 없나 | 1차 릴리스는 화면 입력. 입력하기 쉽게 상품 코드순으로 나열하고 Tab 키로 다음 행으로 넘어가게 한다. CSV 투입은 2차 개발 후보(D-27) |
| R-07 | 사토 님 | RPT-01 청구서 | 매출처 주소가 길면 창 봉투의 창에 들어가나 | 수신인란은 창 봉투(長形3号)의 창 위치에 맞추고 주소는 2행까지 줄바꿈. 상세설계에서 인쇄 위치를 확정하고 실제로 인쇄해 확인받는다 |
| R-08 | 다나카 부장 | 13 권한 매트릭스 | 스즈키 과장과 나는 직접 수주도 등록하는데 발주 승인도 할 수 있나 | 「영업 담당」과 「승인자」를 둘 다 부여하므로 가능. 발주 신청은 물류 담당이 하므로 자기 신청을 승인하는 상황은 생기지 않는다 |
